## 1. Reading the ledger

Each capability has exactly one implementation status:

- **Baseline** — implemented through the canonical lifecycle with sufficient evidence for the
  bounded outcome stated in the row;
- **Partial** — real implementation exists, but delivery, reachability, or required evidence is
  incomplete;
- **Planned** — approved future work without a current implementation claim;
- **Deprecated** — compatibility-only implementation intended for retirement or migration; or
- **Blocked** — cannot safely proceed without unresolved authority, contract, or external system.

Evidence is listed separately using only: contract/schema; deterministic unit; integration;
browser/E2E; real-provider; retained human visual review; Vesko staging; production.

Capability-chain abbreviations are:

| Code | Canonical stage             |
| ---- | --------------------------- |
| R    | registered                  |
| Q    | runtime-queryable           |
| Pl   | planner-selectable          |
| Pr   | proposal-expressible        |
| C    | compiler-preserved          |
| S    | `StorefrontSnapshot`-stored |
| V    | renderer-visible            |
| Ed   | editor-accessible           |
| Sv   | save/reload preserved       |
| Pb   | publish preserved           |
| Ev   | evidence retained           |

`Yes` means the row has direct repository evidence for that stage. `Partial` means a path exists but
has a reachability, parity, environment, or evidence gap. `No` means the stage is absent. `N/A`
means the stage does not apply to that authority. A chain is assessed against the row's bounded
outcome, not against an implied commercial or production claim.
