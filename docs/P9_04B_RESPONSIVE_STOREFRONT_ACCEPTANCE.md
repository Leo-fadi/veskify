# P9-04B — Whole-storefront responsive presentation acceptance

## Scope and viewport matrix

P9-04B validates rendered storefront presentation only. The acceptance matrix is 375 px, 768 px, 1024 px and 1440 px, with English and Finnish coverage where label length changes the layout.

## Homepage

The three registered design directions remain distinct: premium editorial uses the spacious full-bleed and editorial card family; modern technical uses compact commerce; warm approachable uses the balanced editorial family. Every recipe keeps the header before storefront content and the footer after it. Hero copy, calls to action, category discovery, product cards, story, campaign and trust sections remain responsive presentation concerns; recipe order and required-section semantics are unchanged.

## Collection presentation

Dynamic collection presentation keeps canonical collection membership and merchandising order. At compact widths filters remain available through their native disclosure control, while desktop sidebar and horizontal layouts retain their registered arrangements. Product cards preserve title, price, availability, media and canonical product navigation.

## Product-detail presentation

Dynamic PDP presentation preserves canonical product facts, variant selection, unavailable states, gallery media and text-entry option behaviour. At 375 px option controls, engraving input and purchase information remain reachable without horizontal page overflow. Gallery, contained, editorial and split treatments remain presentation-only.

## Product cards and image treatments

Minimal product-first, editorial image-led, compact commerce and premium jewellery card families retain canonical price, compare-at price, availability, image and navigation semantics. Full-bleed, contained, editorial crop, product-neutral, split and framed treatments only affect layout and crop presentation; they do not alter canonical media, decorative state or alternative text.

## Localisation and layout boundaries

Finnish navigation, calls to action, filters, sorting and PDP labels are checked at responsive widths. Storefront header navigation now uses flexible, bounded tracks so localized labels wrap rather than expanding the page width. This change is isolated to rendered storefront styling.

## Preserved boundaries and next checkpoint

No recipe IDs, direction-selection logic, planner contracts, editor shell, proposal review, commerce projections, products, variants, prices, inventory, media authority or navigation ownership changes are part of P9-04B. The remaining integration checkpoint is end-to-end generation and publication acceptance against the same canonical storefront projections.
