# AR-05A implementation approach

The canonical content remains in `StorefrontSnapshot`. Add one strict reference-only
compiled value in the lower domain, a pure compiler, and an application validator
that reuses actual PageBlueprint candidate, structural and responsive authority.
Creation and untrusted reading share semantic validation. Store no second content
tree, layout language, style payload or snapshot fingerprint inside the value.

Bind exact owner, blueprint, component/variant, content references and versioned
application-supplied realization support. Preserve complete visible inventory and
meaningful region-unit order while ignoring storage-only permutations. Unsupported
anatomy, missing support, stale identities, impossible cardinalities and unsafe
omissions fail deterministically without mutating canonical input or controls.

The approved AC-02 amendment requires positive static compile/serialize/revalidate
proof and rule-specific rejection of actual indivisible collection/search and PDP
inventories. Dynamic reference types and applicable validation remain. Reject
duplicate presentations, fabricated anatomy, unconditional dynamic rejection and
test-descriptor claims of rendered fidelity.

The current consumers are the compiler, validator and focused conformance tests.
AR-05B must attach this same value with explicit version dispatch and fingerprint
participation. AR-06 executable commerce support, or its explicitly scoped child,
must prove positive collection/search and PDP composition before enabling them.
Neither successor is implemented here. AR-05 remains Partial; AR-02/03/04 stay closed.

The initial contract incorporates both exact historical source-guard additions and
the owner-approved AC-02 amendment. Earlier drafts, blocker records and the original
legacy baseline remain retained under their original identities. No unresolved
architecture conflict remains within this amended task scope.
