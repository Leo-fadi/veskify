# AR-05 canonical acceptance

AR-05A and AR-05B together address the original AR-00 representation boundary. This record is a
candidate acceptance map only. AR-05B and parent AR-05 become **Baseline / closed only upon accepted
merge**, after the independent verification and delivery gates named by its locked contract.

## Original requirements

- **T01 — Legacy canonical replay** (`AR_00_SOURCE_DISPOSITION_AND_ACCEPTANCE.md:686`): supported
  v1 snapshots retain their documented parse, read, render, and publication observations without
  write-back. AR-05B preserves absent-marker legacy parsing and keeps operational consumers strict;
  a composed value is rejected before legacy projection, save, history, proposal, or publication
  can flatten it.
- **T02 — Composition integrity** (`AR_00_SOURCE_DISPOSITION_AND_ACCEPTANCE.md:687`): all
  section/region references resolve, and unknown relations or impossible reading orders reject.
  AR-05A supplies the compiled reference validation; AR-05B binds it to canonical owners, provides
  explicit snapshot and dynamic authority dispatch, and includes composition in canonical identity.
  It does not create a parallel page tree or let retained profiles become layout authority.

## Deferred AR-06 handoff

AR-06 remains unstarted. It must supply one shared registered renderer, lossless Puck/save/history/
publication integration, four-width visual evidence, and executable commerce support that proves
positive collection/search and PDP composition before dynamic templates can be enabled. AR-05B's
structural v2 representation and current rule-specific dynamic rejection are not that proof.
