## Evidence rules

One row records one claim. A merged implementation without the required test, browser, screenshot
or provider artifact is **Partial**, not complete. Empty evidence is written as **Not retained** or
**Not run**; it is never inferred from a document or a green unrelated test.

Required columns are requirement/AC, task, PR, commit, test, browser, screenshot, provider, status
and limitation. A future Phase 9 closing PR must replace every required Partial/Missing cell with a
safe retained artifact or an explicit approved exception.

## Phase 9 closing rule

Phase 9 closes only when the selected real-provider result:

1. starts from an authoritative Storefront Design Brief that the merchant reviewed and explicitly
   approved;
2. records project ID, brief ID, approved revision/fingerprint, approval state,
   actor/action/timestamp and runtime request/proposal correlation;
3. proves runtime generation used that exact approved revision and that no later unapproved brief
   mutation supplied generation;
4. produces a meaningful compatible shared frame, homepage, collection and dynamic PDP;
5. uses only live registered and compiler-preserved capabilities;
6. preserves canonical commerce and approved asset provenance;
7. passes proposal review, atomic accept, stale/invalid rejection and exact undo;
8. survives Save draft, reload, preview and explicit publish through the same
   `StorefrontSnapshot`;
9. passes EN/FI browser evidence at 375, 768, 1024 and 1440 px without leakage, clipping or
   inaccessible controls.

The required lifecycle is authoritative brief creation → merchant review → explicit approval →
recorded approved revision/fingerprint → runtime generation with that exact revision → correlated
proposal → storefront review and acceptance. Token-only success, PR #123, mocked provider
transport, deterministic fixtures, a merely validated/unapproved brief or an API response cannot
satisfy this closing rule alone.
