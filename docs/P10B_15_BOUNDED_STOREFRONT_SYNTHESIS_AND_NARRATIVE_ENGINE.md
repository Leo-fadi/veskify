# P10B-15 — Bounded Storefront Synthesis and Narrative Engine

## Status

**Baseline — 10 August 2026.** P10B remains **Partial**. P10B-16 coordinated directions and
diversity control, P10B-17 responsive/accessibility/performance closure, and P10B-18 commercial
quality and scale remain **Planned**.

Provider calls: **zero**.

## Outcome

P10B-15 generalizes the P10B-14 complete-store convergence proof into one deterministic bounded
synthesis authority. A typed merchant intent now narrows current registered authority into a
coherent page set, shared frame, Design DNA direction, PageBlueprint profile set, component
anatomies, bounded parameters, narrative sequence, evidence composition, merchandising posture,
art direction, and responsive posture.

The result continues through the existing whole-storefront plan and proposal compiler into one
validated `StorefrontSnapshot`. It does not create a template engine, page graph, renderer,
component registry, product-card system, commerce model, or generated frontend-code path.

```text
approved evidence + read-only commerce + approved assets
+ BrandSystem / Design DNA + site-map/page families
+ registered PageBlueprint profiles + component capabilities
→ versioned bounded synthesis decision
→ existing whole-storefront plan/proposal
→ validated StorefrontSnapshot
→ save/reload → preview → deterministic publication
```

## Canonical authority placement

The synthesis authority lives immediately before the existing coordinated whole-storefront
planner. It chooses only current registered references. The reusable complete-store materializer
then converges the existing P10B-05, P10B-09 through P10B-13, proposal, snapshot, registry, and
renderer authorities. The P10B-14 materializer now delegates to this same canonical convergence
layer while retaining its prior deterministic section identities and evidence.

`StorefrontSnapshot` remains the sole editable and rendering aggregate. The synthesis decision is
traceability metadata; it never becomes a second persisted page representation.

## Versioned synthesis contract

Contract version `1` records:

- request intent and deterministic seed;
- merchant/project/approved-brief fingerprint;
- sorted approved evidence revision set;
- exact canonical commerce fingerprint;
- approved-asset authority fingerprint;
- selected registered Design DNA direction and fingerprint;
- chosen site-map/page-set fingerprint and page keys;
- one shared-frame profile/version/authority fingerprint;
- homepage, collection, search, and PDP profile selections;
- every page-family/profile version and structural fingerprint;
- cross-page narrative posture, role sequence, contributions, discovery path, and conversion path;
- merchandising, information-density, art-direction, and responsive posture;
- exact component/variant/anatomy choices and current capability fingerprints;
- bounded parameter projection;
- required, optional, and evidence-omitted pages;
- current whole-storefront target, component-registry, and recipe-context fingerprints;
- explicit machine-readable selection/narrowing outcomes; and
- one deterministic synthesis fingerprint covering the complete material.

The fingerprint is recomputed by schema validation. Execution additionally recomputes the entire
decision from current authority and requires canonical equality. A caller cannot repair a stale
reference merely by supplying a new hash.

## Bounded request vocabulary

The current request vocabulary is:

- `editorial-led`;
- `commerce-led`;
- `restrained-minimal`;
- `dense-catalogue`;
- `high-consideration`;
- `campaign-emphasis`; and
- `stronger-brand-storytelling`.

These values narrow authority. They cannot authorize new page families, variants, bindings,
assets, facts, CSS, HTML, JSX, scripts, or React components. Unknown values fail validation.

A dense-catalogue request requires sufficient canonical product density. The small retained Lumo
catalogue is explicitly narrowed to editorial discovery and records `dense-request-narrowed`; a
larger canonical catalogue selects the registered dense/search profile. Campaign emphasis requires
current approved editorial media and a common compatible frame across the complete chosen page
set. An impossible campaign or frame/profile combination fails closed.

## Narrative coordination

The engine consumes the canonical PageBlueprint narrative roles rather than inventing a parallel
vocabulary. Current roles are `orientation`, `primary-discovery`, `secondary-discovery`,
`product-focus`, `product-proof`, `brand-story`, `brand-proof`, `education`, `campaign`, `trust`,
`service`, `conversion`, and `continuation`.

Each selected page/profile contributes its exact registered slot roles. The engine:

- coordinates homepage introduction/story/discovery with collection and search discovery;
- uses catalogue shape and configurable-product presence to choose compatible PDP depth;
- retains approved brand/support/service contributions;
- verifies a catalogue discovery path when collection/search pages exist;
- verifies a conversion path through product focus and governed cart/checkout presentation;
- rejects three consecutive identical roles within a selected page profile; and
- compresses adjacent duplicates only in the traceability sequence, never in the PageBlueprint.

This metadata is explicit selection evidence, not private model reasoning or chain-of-thought.

## Evidence, commerce, media, and compatibility

Required factual pages must resolve exact current approved evidence. Optional factual pages whose
requested evidence is unavailable are omitted before site-map mutation and recorded explicitly.
The synthesis decision cannot add filler or fabricate merchant, policy, delivery, guarantee,
certification, service, or compliance claims.

Catalogue size, collection membership, and configurable order options influence bounded profile
selection. Products, variants, options, SKUs, prices, availability, stock, collections, and
membership remain unchanged. Collection materialization resolves the page's exact canonical
collection context. Product pages continue through the generic dynamic PDP and P6 option authority.

Approved assets remain bound by their existing approval fingerprint, revision, provenance,
presentation role, focal/safe area, derivative authority, and material fingerprint. Editorial
media cannot replace canonical product media. Product-detail sections continue to resolve product
media from read-only commerce.

All selected PageBlueprint profiles must share one registered P10B-06 frame. Every slot must resolve
its exact component and variant from the current component definitions. Invalid frame/profile,
profile/version, narrative, component/variant, evidence, commerce, asset, registry, recipe, or
whole-storefront references fail before materialization.

## Deterministic selection and explainability

Selection is deterministic; there is no random fallback. The same canonical inputs, request, and
seed produce the same decision, synthesis fingerprint, plan, and snapshot fingerprint. A changed
bounded intent can change several architectural dimensions, including Design DNA, homepage flow,
collection posture, PDP depth, component anatomy, narrative sequence, density, art direction, and
responsive posture.

The decision retains small machine-readable outcomes such as:

- `story-authority-selected`;
- `restrained-authority-selected`;
- `commerce-authority-selected`;
- `dense-request-narrowed`; and
- `campaign-authority-selected`.

Each outcome cites public authority references such as request ID, catalogue count,
configurable-product presence, or approved asset role. It stores no prompt, provider response,
secret, or hidden reasoning.

## Fail-closed boundary

The engine rejects invalid request vocabulary, stale contract or fingerprints, stale profiles,
stale component capability, incompatible frame/profile sets, unsupported narrative roles,
impossible discovery/conversion coverage, unavailable required evidence, campaign evidence gaps,
invalid bounded values, and any decision that differs from recomputed current authority. Failure
occurs before `StorefrontSnapshot` mutation and creates no partial proposal or store.

## Deferred authority

P10B-16 remains responsible for coordinated commercial direction packages, diversity measurement,
exact and meaningful near-duplicate control, pairwise comparison, and scale-oriented design
fingerprints. P10B-17 remains responsible for phase-wide responsive, accessibility, and performance
closure. P10B-18 remains the 100+ configuration commercial quality and diversity gate.
